# MVP scope (draft)

The MVP exists to answer one question: does showing a personal dream at the moment of distraction get people back to their task?

## In scope

- Create and edit one or more dream profiles (title, image, personal "why").
- Start a focus session tied to a dream action.
- Detect when a user-chosen distracting app opens during a session.
- Show the dream interruption screen with a one-tap return.
- Local storage only. Fully offline.
- Onboarding that explains the permissions in plain words.

## Out of scope for the MVP

- Accounts, sync or any server.
- AI-generated plans or messages.
- Hard-lock or tamper-resistant modes.
- Catch-up windows and commitment mode (Phase 3).
- Hardware (ESP32 beacon).

## Success signals

- Testers return to the task after an interruption more often than they dismiss it.
- Testers say the screen felt supportive, not nagging.
- No tester reports feeling guilty or shamed.

## Open questions

- Accessibility service versus usage access plus overlay, given Play policy.
- How many apps a user should be able to mark as distracting at first run.
